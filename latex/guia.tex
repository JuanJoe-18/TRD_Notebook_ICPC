\subsection*{2.1 El Peligro Fatal de Fenwick (BIT)}
En el Fenwick Tree:
\begin{lstlisting}
void add(int idx, ll val) {
  for (; idx <= n; idx += idx & -idx) bit[idx] += val;
}
\end{lstlisting}
Si se llama con \texttt{idx = 0}, la operación \texttt{0 \& -0} da \texttt{0}, resultando en un \textbf{bucle infinito} que genera TLE inexplicable. Si tus datos son 0-based, haz siempre \texttt{ft.add(x + 1, val)} y \texttt{ft.query(l + 1, r + 1)}.

\subsection*{2.2 DSU con Problemas 1-based}
Como el constructor de \texttt{DSU(n)} inicializa de $0$ a $n-1$, si el problema da vértices $1 \dots n$, simplemente inicializa \texttt{DSU dsu(n + 1)}. El nodo 0 existirá pero quedará aislado sin afectar las componentes $1 \dots n$.

\subsection*{2.3 Euler Tour (Aplanamiento de Árbol)}
Para mapear subárboles a rangos contiguos en un Segment Tree:
\begin{lstlisting}
int timer = 0;
vi tin(n + 1), tout(n + 1), flat(n + 1);
void dfs_flat(int u, int p) {
  tin[u] = ++timer;
  flat[timer] = u;
  for (int v : adj[u]) if (v != p) dfs_flat(v, u);
  tout[u] = timer;
}
// El subarbol de u es exactamente el rango: [tin[u], tout[u]]
\end{lstlisting}

\section*{3. Modificabilidad Avanzada: Recetario de Funciones}

\subsection*{3.1 Dijkstra Multi-Estado (Estado Extendido)}
Cuando el costo no solo depende del vértice, sino de un recurso (ej. $K$ boletos de descuento, paridad de pasos, combustible):
\begin{enumerate}
  \item Define el estado como una tupla: \texttt{(nodo, recurso)}.
  \item La matriz de distancias pasa a ser \texttt{dist[N][K+1]}.
  \item El heap contiene \texttt{\{costo, \{nodo, recurso\}\}}.
\end{enumerate}

\begin{lstlisting}
vector<vll> dist(n + 1, vll(k + 1, LINF));
using Item = pair<ll, pair<int, int>>;
priority_queue<Item, vector<Item>, greater<Item>> pq;

dist[src][k] = 0;
pq.push({0, {src, k}});

while (!pq.empty()) {
  auto [d, state] = pq.top(); pq.pop();
  auto [u, rem] = state;
  if (d > dist[u][rem]) continue;

  for (int id : g.adj[u]) {
    auto& e = g.edges[id];
    // Transicion normal (costo completo)
    if (dist[u][rem] + e.weight < dist[e.to][rem]) {
      dist[e.to][rem] = dist[u][rem] + e.weight;
      pq.push({dist[e.to][rem], {e.to, rem}});
    }
    // Transicion especial (usando 1 descuento)
    if (rem > 0) {
      ll w2 = dist[u][rem] + e.weight / 2;
      if (w2 < dist[e.to][rem - 1]) {
        dist[e.to][rem - 1] = w2;
        pq.push({w2, {e.to, rem - 1}});
      }
    }
  }
}
\end{lstlisting}

\subsection*{3.2 Reconstrucción de Caminos (Path Recovery)}
Para recuperar la ruta en Dijkstra, BFS o 0-1 BFS:
\begin{lstlisting}
// Vector de padres inicializado en -1: vi p(n + 1, -1);
// Al relajar: p[e.to] = u;
vi restore_path(int target, const vi& p) {
  vi path;
  for (int v = target; v != -1; v = p[v]) path.pb(v);
  reverse(all(path));
  return path; // Retorna {src, ..., target}
}
\end{lstlisting}

\subsection*{3.3 Segment Tree: Desacoplamiento de Nodo}
No modifiques los índices del árbol. Solo redefine el \texttt{struct Node} y la función \texttt{merge}:

\begin{lstlisting}
// Ejemplo: Max Subarray Sum en O(log N)
struct Node {
  ll sum, pref, suff, ans;
  Node(ll v = 0) {
    sum = v;
    pref = suff = ans = max(0LL, v);
  }
};

Node merge(const Node& a, const Node& b) {
  Node res;
  res.sum = a.sum + b.sum;
  res.pref = max(a.pref, a.sum + b.pref);
  res.suff = max(b.suff, b.sum + a.suff);
  res.ans = max({a.ans, b.ans, a.suff + b.pref});
  return res;
}
\end{lstlisting}

\subsection*{3.4 Segment Tree con Lazy Propagation Canónico}
El secreto para no confundirse con Lazy es respetar dos reglas:
\begin{itemize}
  \item \textbf{Aplicar al nodo:} Al aplicar una etiqueta a un nodo, se debe actualizar su valor real y combinar su etiqueta lazy pendiente.
  \item \textbf{Empujar a los hijos:} Solo empuja a los hijos antes de descender.
\end{itemize}

\begin{lstlisting}
struct LazySegTree {
  int n;
  vll st, lazy;
  LazySegTree(int n) : n(n), st(4*n, 0), lazy(4*n, 0) {}

  void apply(int p, int l, int r, ll val) {
    st[p] += (r - l + 1) * val; // Actualiza valor
    lazy[p] += val;             // Acumula tag
  }
  void push(int p, int l, int r) {
    if (lazy[p] == 0) return;
    int mid = (l + r) / 2;
    apply(2*p, l, mid, lazy[p]);
    apply(2*p+1, mid+1, r, lazy[p]);
    lazy[p] = 0;
  }
  void update(int p, int l, int r, int ql, int qr, ll val) {
    if (ql <= l && r <= qr) { apply(p, l, r, val); return; }
    push(p, l, r);
    int mid = (l + r) / 2;
    if (ql <= mid) update(2*p, l, mid, ql, qr, val);
    if (qr > mid)  update(2*p+1, mid+1, r, ql, qr, val);
    st[p] = st[2*p] + st[2*p+1];
  }
  ll query(int p, int l, int r, int ql, int qr) {
    if (ql <= l && r <= qr) return st[p];
    push(p, l, r);
    int mid = (l + r) / 2;
    ll res = 0;
    if (ql <= mid) res += query(2*p, l, mid, ql, qr);
    if (qr > mid)  res += query(2*p+1, mid+1, r, ql, qr);
    return res;
  }
};
\end{lstlisting}

\subsection*{3.5 HLD sobre Aristas (Edge Updates)}
Para actualizar o consultar caminos con valores en las aristas:
\begin{enumerate}
  \item Cada arista $(u, v)$ se asigna al nodo hijo: $\text{child} = (\text{depth}[u] > \text{depth}[v] ? u : v)$.
  \item Al recorrer cadenas en HLD, cuando ambos nodos $u$ y $v$ quedan en la misma cadena pesada con $\text{pos}[u] \le \text{pos}[v]$, la consulta debe ser:
  \begin{lstlisting}
  if (u != v) {
    res = merge(res, segtree.query(pos[u] + 1, pos[v]));
  }
  \end{lstlisting}
  El \texttt{+1} excluye la arista que sube desde el LCA hacia su padre.
\end{enumerate}

\subsection*{3.6 DP con Rerooting (Todos los Nodos como Raíz)}
Problema tipo: "Calcula para cada nodo $u$ la suma de distancias / mejor camino si $u$ fuera la raíz del árbol".
\begin{itemize}
  \item \textbf{Paso 1 (DFS Bottom-up):} Calcula $dp[u]$ combinando los estados de sus hijos.
  \item \textbf{Paso 2 (DFS Top-down / Rerooting):} Al pasar la raíz de $u$ a un hijo $v$, se extrae la contribución de $v$ del estado de $u$ (usando prefijos y sufijos de hijos si la operación no es invertible) y se le añade a $v$ como nuevo hijo.
\end{itemize}

\begin{lstlisting}
struct State { ll sz, sum; };
State merge_sub(State a, State b) {
  return {a.sz + b.sz, a.sum + b.sum + b.sz};
}
// Al mover la raiz de u a v:
// 1. Quitar a v de u
// 2. Insertar u en v
\end{lstlisting}

\subsection*{3.7 Optimización Divide and Conquer (D\&C DP)}
Aplica a recurrencias de la forma:
$$dp[i][j] = \min_{k < j} (dp[i-1][k] + C[k][j])$$
donde el punto óptimo $opt[i][j]$ es monótono: $opt[i][j-1] \le opt[i][j] \le opt[i][j+1]$. Reduce la complejidad de $O(K N^2)$ a $O(K N \log N)$.

\begin{lstlisting}
void compute(int i, int l, int r, int optl, int optr) {
  if (l > r) return;
  int mid = (l + r) / 2;
  pair<ll, int> best = {LINF, -1};
  for (int k = optl; k <= min(mid - 1, optr); k++) {
    best = min(best, {dp[i-1][k] + cost(k, mid), k});
  }
  dp[i][mid] = best.first;
  int opt = best.second;
  compute(i, l, mid - 1, optl, opt);
  compute(i, mid + 1, r, opt, optr);
}
\end{lstlisting}

\subsection*{3.8 SOS DP (Sum Over Subsets)}
Dada una función $A$ sobre máscaras de bits, calcula para cada máscara $mask$ la suma de todos sus subconjuntos $sub \subseteq mask$:
$$F[mask] = \sum_{sub \subseteq mask} A[sub]$$
Fuerza bruta sobre submáscaras toma $O(3^N)$. Con SOS DP se logra en $O(N 2^N)$:

\begin{lstlisting}
// dp inicializado con los valores base a[mask]
for (int i = 0; i < N; i++) {
  for (int mask = 0; mask < (1 << N); mask++) {
    if (mask & (1 << i)) {
      dp[mask] += dp[mask ^ (1 << i)];
    }
  }
}
\end{lstlisting}

\section*{4. Marco Teórico: DP como Autómatas y DAGs}

Cuando un problema de Programación Dinámica parece inabordable o multidimensional (DP ``HARD''), modelarlo formalmente como un \textbf{Autómata Finito Determinista (DFA)} y su \textbf{Grafo Acíclico Dirigido (DAG)} inducido elimina toda ambigüedad.

\subsection*{4.1 La 5-Tupla Formal $\mathcal{M} = (Q, \Sigma, \delta, q_0, F)$}
Todo problema de DP se formaliza rigurosamente como:
\begin{itemize}
  \item \textbf{Espacio de Estados ($Q$):} Conjunto de subproblemas discretos. Es la \textit{memoria mínima y suficiente} para tomar decisiones futuras sin violar el principio de optimalidad de Bellman.
  \item \textbf{Alfabeto de Decisiones ($\Sigma$):} Conjunto finito de transiciones o decisiones atómicas permitidas.
  \item \textbf{Función de Transición ($\delta: Q \times \Sigma \to Q \cup \{\emptyset\}$):} Regla determinista que calcula el sucesor $q' = \delta(q, a)$. Si la decisión $a$ infringe restricciones, conmuta a $\emptyset$ (transición prohibida).
  \item \textbf{Estado Inicial ($q_0 \in Q$):} Caso base trivial de partida.
  \item \textbf{Conjunto de Aceptación ($F \subseteq Q$):} Estados finales que representan la resolución del problema global.
\end{itemize}

\subsection*{4.2 Las 3 Preguntas Universales de Diseño}
Ante cualquier DP complejo en competencia, responde en papel:
\begin{enumerate}
  \item \textbf{Eje de Avance:} ¿Qué variable escalar cuantifica el progreso monótono hacia $F$? (índice, suma, tiempo, bits encendidos). Esto garantiza ausencia de ciclos y define el orden topológico.
  \item \textbf{Memoria Mínima:} ¿Cuál es la mínima información histórica indispensable para dictaminar si $\delta(q, a)$ es legal? (purgar toda variable que no condicione el futuro).
  \item \textbf{Decisiones Legales:} ¿Qué aristas $\Sigma$ emanan del estado actual y qué invariantes o penalidades imponen?
\end{enumerate}

\subsection*{4.3 Permutaciones vs Combinaciones (1D vs 2D)}
Al contar composiciones de un alfabeto $\Sigma = \{c_1, \dots, c_n\}$ que alcanzan una suma $S$:
\begin{itemize}
  \item \textbf{Permutaciones (1D - Dice / Coin Comb. I):}
  El estado es solo la suma $s \in Q$. En cada paso se itera sobre \textit{todo el alfabeto $\Sigma$}:
  $$dp[s] = \sum_{c \in \Sigma} dp[s - c]$$
  Distingue órdenes distintos: $[1, 2]$ y $[2, 1]$ forman caminos distintos en el DAG.
  \item \textbf{Combinaciones (2D - Knapsack / Coin Comb. II):}
  Para colapsar órdenes equivalentes, se expande el estado a $(i, s)$ acotando el prefijo de decisiones permitidas a $\{c_1, \dots, c_i\}$:
  $$dp[i][s] = dp[i-1][s] + dp[i][s - c_i]$$
  Fuerza un orden topológico no decreciente, garantizando que cada combinación se cuente una sola vez.
\end{itemize}

\subsection*{4.4 Isomorfismo Universal con Grafos (DAGs)}
Toda recurrencia de DP se reduce a caminos sobre el DAG inducido $G=(V, E)$ donde $V = Q$ y $E = \{(u, v) \mid \exists a : \delta(u, a) = v\}$:
\begin{itemize}
  \item \textbf{Mínimo Costo:} Camino más corto desde $q_0$ hasta $F$.
  \item \textbf{Máximo Beneficio:} Camino más largo en el DAG.
  \item \textbf{Conteo de Maneras:} Número de caminos dirigidos entre $q_0$ y $F$ (convergencia modular).
\end{itemize}

\section*{5. Grillas ($R \times C$) y Extrapolaciones}

\subsection*{5.1 Mapeo Lineal (Flattening)}
Convierte coordenadas 2D a un ID entero 1D:
\begin{lstlisting}
auto get_id = [&](int r, int c) { return r * C + c; };
auto get_row = [&](int id) { return id / C; };
auto get_col = [&](int id) { return id % C; };
\end{lstlisting}

\subsection*{5.2 Bipartición de Grillas (Tablero de Ajedrez)}
Toda grilla con movimientos ortogonales (arriba, abajo, izquierda, derecha) es un \textbf{grafo bipartito}:
\begin{itemize}
  \item Conjunto A (Blancas): $(r + c) \pmod 2 == 0$.
  \item Conjunto B (Negras): $(r + c) \pmod 2 == 1$.
\end{itemize}
\textbf{Aplicaciones Inmediatas:}
\begin{itemize}
  \item \textit{Colocar dominós $1 \times 2$ sin superposición:} Es exactamente el Emparejamiento Bipartito Máximo (Max Bipartite Matching) entre Blancas y Negras.
  \item \textit{Mínimas celdas a bloquear para evitar dominós:} Por el Teorema de König, en grafos bipartitos:
  $$\text{Min Vertex Cover} = \text{Max Matching}$$
  $$\text{Max Independent Set} = (\text{Total Celdas}) - \text{Max Matching}$$
\end{itemize}

\subsection*{5.3 Flujo con Capacidad en Celdas}
Si una celda $(r, c)$ solo puede ser atravesada $K$ veces por caminos disjuntos:
\begin{itemize}
  \item Divide cada celda $u$ en dos subnodos: $u_{in}$ y $u_{out}$.
  \item Agrega arista interna: $u_{in} \to u_{out}$ con capacidad $K$.
  \item Para vecinos transitables $v$, conecta: $u_{out} \to v_{in}$ con capacidad $\infty$.
\end{itemize}

\section*{6. Reconocimiento de Problemas Complejos}

\subsection*{6.1 Min-Cut / Project Selection (Selección de Proyectos)}
\textbf{Patrón del Enunciado:}
\begin{itemize}
  \item Hay proyectos que otorgan una ganancia positiva $P_i$.
  \item Hay herramientas o licencias que cuestan $C_j$.
  \item Restricción de dependencia: \textit{"Para realizar el proyecto $i$, es obligatorio comprar la herramienta $j$"}.
  \item Se desea maximizar la ganancia neta.
\end{itemize}

\textbf{Reducción a Min-Cut:}
\begin{enumerate}
  \item Conecta la Fuente $S \to \text{Proyecto}_i$ con capacidad $P_i$.
  \item Conecta cada $\text{Herramienta}_j \to \text{Sumidero } T$ con capacidad $C_j$.
  \item Conecta $\text{Proyecto}_i \to \text{Herramienta}_j$ con capacidad $\infty$.
  \item $\text{Respuesta} = \sum (\text{Todas las Ganancias}) - \text{Dinic.min\_cut}(S, T)$.
\end{enumerate}

\subsection*{6.2 2-SAT Implícito}
\textbf{Patrón del Enunciado:}
Problemas donde cada elemento tiene exactamente 2 estados excluyentes ($0$ o $1$, Izquierda o Derecha, Sala A o Sala B) y te dan restricciones por pares:
\begin{itemize}
  \item \textit{"No pueden estar ambos activos":} $\neg (A \land B) \iff (A \implies \neg B) \land (B \implies \neg A)$.
  \item \textit{"Al menos uno debe estar activo":} $(A \lor B) \iff (\neg A \implies B) \land (\neg B \implies A)$.
  \item \textit{"Deben ser iguales":} $(A \iff B) \iff (A \implies B) \land (B \implies A) \land (\neg A \implies \neg B) \land (\neg B \implies \neg A)$.
\end{itemize}
\textbf{Solución:} Si $x$ y $\neg x$ están en la misma componente fuertemente conexa (SCC), es imposible. De lo contrario, la asignación es válida.

\subsection*{6.3 Flujos con Demandas Mínimas (Circulación)}
Si cada arista $e = (u, v)$ exige un flujo dentro de un rango $[L_e, R_e]$:
\begin{enumerate}
  \item Reemplaza la capacidad por $R_e - L_e$.
  \item Crea una super-fuente $S'$ y un super-sumidero $T'$.
  \item Para cada vértice $u$, define su balance de demanda:
  $$D[u] = \sum_{e \text{ entra a } u} L_e - \sum_{e \text{ sale de } u} L_e$$
  \item Si $D[u] > 0$, añade arista $S' \to u$ con capacidad $D[u]$.
  \item Si $D[u] < 0$, añade arista $u \to T'$ con capacidad $-D[u]$.
  \item Si el flujo máximo desde $S'$ satura todas las aristas que salen de $S'$, existe una circulación válida.
\end{enumerate}

\subsection*{6.4 Teorema de Dilworth (Anticadenas en DAGs)}
En un conjunto parcialmente ordenado (DAG transitivo):
\begin{itemize}
  \item \textbf{Cadena:} Secuencia donde cada elemento es menor que el siguiente.
  \item \textbf{Anticadena:} Conjunto de elementos donde ninguno es comparable con otro.
  \item \textbf{Teorema:} El tamaño de la \textbf{máxima anticadena} es igual al número mínimo de caminos disjuntos en vértices que cubren todo el DAG (resoluble con Bipartite Matching duplicando vértices).
\end{itemize}

\subsection*{6.5 BFS 0-1 (Grafos Implícitos)}
Si las transiciones entre estados tienen costo estrictamente $0$ o $1$:
\begin{itemize}
  \item \textbf{NUNCA} uses Dijkstra ($O(E \log V)$).
  \item Usa \texttt{ZeroOneBfs} con \texttt{std::deque}:
  \begin{itemize}
    \item Si la arista pesa 0: \texttt{dq.push\_front(\{v, d\})}.
    \item Si la arista pesa 1: \texttt{dq.push\_back(\{v, d + 1\})}.
  \end{itemize}
  Complejidad $O(V + E)$ en tiempo lineal estricto.
\end{itemize}

\subsection*{6.6 Meet-in-the-Middle}
\textbf{Señal inequívoca:} $N \approx 36 \dots 42$.
\begin{itemize}
  \item $2^{40} \approx 10^{12} \implies$ Imposible en 1 segundo.
  \item Divide en dos mitades de tamaño $N/2 \approx 20$:
  \begin{itemize}
    \item Mitad 1: Genera los $2^{20} \approx 10^6$ valores en un vector $A$ y ordénalo.
    \item Mitad 2: Para cada uno de los $2^{20}$ valores $x$ de la mitad 2, busca en $A$ con \texttt{std::lower\_bound} el complemento óptimo.
  \end{itemize}
  Complejidad: $O(2^{N/2} \cdot \frac{N}{2}) \approx 2 \times 10^7$ operaciones (entra sobrado en 1 segundo).
\end{itemize}

\subsection*{6.7 Búsqueda Binaria sobre la Respuesta}
Sospecha inmediata ante las siguientes frases:
\begin{itemize}
  \item \textit{"Minimizar el máximo valor..."}
  \item \textit{"Maximizar el mínimo valor..."}
  \item \textit{"Halla el menor tiempo tal que..."}
\end{itemize}
Verifica la propiedad de monotonía: Si con valor $M$ es posible, ¿también es posible con $M+1$? Si la respuesta es sí, busca binariamente en el rango $[\text{low}, \text{high}]$.

\section*{7. Strings y Hashing Anti-Hack}

\subsection*{7.1 Rolling Hash con Base y Módulo Seguros}
En plataformas como Codeforces o competencias con tests generados con cadenas de Thue-Morse, el módulo $10^9+7$ o bases fijas como $31$ son vulnerables a colisiones forzadas intencionalmente. Usa siempre:
\begin{itemize}
  \item Módulo grande primo: $M = 10^9 + 9$ o $2^{61}-1$.
  \item Base aleatoria generada en tiempo de ejecución: $B \in [257, M - 2]$ con \texttt{rng}.
\end{itemize}

\begin{lstlisting}
const ll MOD = 1e9 + 9;
ll B; // Inicializado en main con rand_val(300, MOD - 2)

struct StringHash {
  vll h, p;
  StringHash(const string& s) {
    int n = s.size();
    h.assign(n + 1, 0); p.assign(n + 1, 1);
    for (int i = 0; i < n; i++) {
      h[i + 1] = (h[i] * B + s[i]) % MOD;
      p[i + 1] = (p[i] * B) % MOD;
    }
  }
  // Hash del substring s[l..r] (0-based)
  ll get(int l, int r) {
    ll res = (h[r + 1] - h[l] * p[r - l + 1]) % MOD;
    return (res + MOD) % MOD;
  }
};
\end{lstlisting}

\subsection*{7.2 Cuándo usar KMP vs Z-Algorithm vs Trie}
\begin{itemize}
  \item \textbf{KMP ($\pi$):} Ideal para encontrar el periodo más corto de una cadena, prefijo que es sufijo, o autómata de búsqueda de 1 patrón en streaming.
  \item \textbf{Z-Algorithm ($Z$):} Ideal para saber para cada sufijo $S[i \dots]$ cuál es el prefijo común más largo (LCP) con toda la cadena. Es mucho más intuitivo de modificar que KMP.
  \item \textbf{Aho-Corasick:} Indispensable si hay \textbf{múltiples patrones} simultáneos que buscar en un solo texto.
\end{itemize}

\section*{8. Geometría Computacional Segura}

\subsection*{8.1 Producto Cruz Entero (Sin Floats)}
Siempre que los puntos tengan coordenadas enteras ($\le 10^8$), calcula la orientación usando \texttt{long long} estricto:
\begin{lstlisting}
ll cross(Point a, Point b, Point c) {
  return 1LL * (b.x - a.x) * (c.y - a.y) - 1LL * (b.y - a.y) * (c.x - a.x);
}
// cross > 0: Giro antihorario (a la izquierda)
// cross < 0: Giro horario (a la derecha)
// cross == 0: Puntos colineales
\end{lstlisting}

\subsection*{8.2 Convex Hull: Colinealidad en el Borde}
En el algoritmo de Monotone Chain:
\begin{itemize}
  \item \textbf{Cáscara estricta (sin colineales):} Usa \texttt{cross(...) <= 0}.
  \item \textbf{Preservando colineales en el borde:} Usa \texttt{cross(...) < 0}.
\end{itemize}

\subsection*{8.3 Intersección de Segmentos Entera}
Para saber si dos segmentos $AB$ y $CD$ se cruzan estrictamente sin usar números flotantes:
\begin{lstlisting}
bool intersect(Point a, Point b, Point c, Point d) {
  auto cp = [](Point p, Point q, Point r) {
    ll v = cross(p, q, r);
    return (v > 0) - (v < 0);
  };
  return cp(a, b, c) * cp(a, b, d) < 0 &&
         cp(c, d, a) * cp(c, d, b) < 0;
}
\end{lstlisting}

\subsection*{8.4 Calipers Rotativos (Rotating Calipers)}
Calcula el diámetro de un polígono convexo en tiempo $O(N)$ encontrando los pares de puntos antípodas mediante avance de puntero monótono en sentido antihorario.

\section*{9. Checklist de Emergencia Pre-Submit}

Antes de presionar Submit y arriesgar una penalización de 20 minutos por Wrong Answer:

\begin{itemize}
  \item[\textbf{[ ]}] \textbf{¿Hay desbordamiento entero (Integer Overflow)?}
  ¿Alguna multiplicación de dos enteros de $10^5$ o suma acumulada supera $2 \times 10^9$? Usa \texttt{1LL * a * b} o define \texttt{\#define int long long}.
  \item[\textbf{[ ]}] \textbf{¿El valor de INF es suficientemente grande?}
  En Dijkstra con pesos de arista hasta $10^9$, \texttt{INT\_MAX} se desborda inmediatamente. Usa \texttt{LINF = 2e18}.
  \item[\textbf{[ ]}] \textbf{¿Múltiples casos de prueba ($T$ testcases)?}
  Verifica que las estructuras globales se limpien con precisión hasta $N$, no reasignando vectores gigantes con \texttt{memset} innecesario que cause TLE ($O(T \cdot \text{MAXN})$).
  \item[\textbf{[ ]}] \textbf{Casos de Borde (Corner Cases):}
  \begin{itemize}
    \item $N = 1$ o $N = 2$.
    \item Árbol con forma de estrella o línea recta (máxima profundidad).
    \item Grafo disconexo (¿el problema exige imprimir $-1$?).
    \item Cadenas vacías o caracteres todos idénticos.
    \item Polígonos de área 0 o puntos superpuestos.
  \end{itemize}
\end{itemize}

\subsection*{9.1 Script de Stress Testing Local (3 minutos)}
Cuando tengas un código con WA y un algoritmo de fuerza bruta confiable ($O(N^2)$), crea un script de testeo rápido en Python:
\begin{lstlisting}[language=Python]
import random, subprocess

for it in range(1000):
  n = random.randint(1, 10)
  a = [random.randint(1, 20) for _ in range(n)]
  data = f"{n}\n" + " ".join(map(str, a)) + "\n"

  out1 = subprocess.check_output("./sol", input=data, text=True)
  out2 = subprocess.check_output("./brute", input=data, text=True)

  if out1.strip() != out2.strip():
    print(f"FAILED on test:\n{data}")
    print(f"Sol: {out1}\nBrute: {out2}")
    break
\end{lstlisting}
